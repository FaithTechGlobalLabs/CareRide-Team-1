# CareRide: Flows and Notes

Draft. **[open]** = undecided or unclear.

## 1. Day-to-day flow

**Client**
1. Has a destination they have to get to
2. Requests a ride from the case manager
3. Waits for the ride (scheduled or otherwise)
4. Gets on the ride
5. Gets off the ride
6. Does their thing
7. (If returning) waits for the ride
8. Gets on the ride
9. Gets off the ride

**Staff / house**
1. Ensure client has a reason for travel / other policies
2. Collect info about destination and travel needs (fixed locations)
3. Find an available transportation option based on criteria
4. Schedule and confirm with client; driver confirms
5. Direct and remind client to go on their ride (driver may show up at the lobby)
6. Confirm person arrived at destination
7. (If returning) confirm person is back on their ride; coordinate if the driver is available

**Driver**
1. Receive a request for a ride to a destination from a specific house
2. Accept the request
3. Go to the pickup location
4. Confirm client has been picked up **[open: draft said "dropped off"]**
5. (If returning) wait for client
6. Pick up client
7. Drop off client
8. Confirm with house that the ride is done

## 2. Notes

### Stakeholders
- Partner orgs
- Transport provider
- Destination
- Client
- Donor (stretch)

### Scope
- Platform is third-party and not owned by the Salvation Army. The Salvation Army is the pilot.
- Fixed, closed A to B locations in Vancouver, e.g. Belkin House to St. Paul's.
- Vision: plug and play.
- Start with Belkin House.
- Point A units (Belkin House communities): Belkin House, Richmond House, Grace Mansion.
- Clients are residents of a specific housing location.
- **No client info in the system.** Clients need no name. A codename might work **[open]**.

### Registration
**Partner org**
- Basic info
- Add point B locations
- Has transport options (e.g. a dedicated vehicle)
  - Specify driver
  - Specify availability and number of spaces

**Transport provider** (e.g. Hope Mission)
- Basic info
- Notifications for bookings
- Specify driver
- Specify availability and number of spaces

### Drivers
- Driver can be unaffiliated, e.g. Frank, an Uber driver who is also a CareRide driver.
- Start with professional drivers (taxi, ride-share). They are already vetted, so we avoid the liability and hoops.
- How a user is verified is on us. **[open: how]**

### Booking
- Each location has **one account**, not a case-manager account.
- Locations are fixed and limited initially, at the discretion of staff. **Preset locations are preferred**, and it is fair for staff to set a location manually.
- Most-visited locations come from each house.
- **One-way trips are the current scope.** A return trip can be scheduled the same way if needed.
- Round trip vs. one-way, and which locations tend toward each, is context staff know how to handle. It is not a system rule.
- A ride can be solo or have multiple people in the car, especially for scheduled rides.
- Help clients provide more info. **[open: unclear what this means for the product]**
- Strong boundary if the client passes up the ride: the client loses the ride.
- Requests vary. Typical requests that justify a 911 call go to 911; CareRide covers the other cases.
- Platform that helps the homeless.

## 3. What a new org or provider goes through

**Partner org:** register, enter basic info, add point B locations, optionally add transport options (driver, availability, spaces), then book from the single location account.

**Transport provider:** register, enter basic info, set booking notifications, specify driver, set availability and spaces, then receive and accept bookings.
